## Highlights

0.5.x is the series where CAIPE became an enterprise platform. It landed seven headline
capabilities: relationship-based fine-grained authorization, an agentic workflow engine,
a Webex bot, bring-your-own credentials for MCP servers, fully UI-defined custom agents,
agent-driven scheduled jobs, and multimodal file attachments in chat.

The whole authorization stack ships **disabled by default**, so upgrading a stock 0.4.18
deployment needs no `values.yaml` edits at all.

## Features

### Fine-grained authorization (0.5.0 onward)

Every access decision — agents, knowledge bases, MCP tools, workflows, credentials —
flows through one relationship-based (ReBAC) authorization stack backed by
[OpenFGA](https://openfga.dev/) and Keycloak.

- **OpenFGA is the source of truth** for team resource access. The admin team UI reflects
  only what the authorization store knows.
- **Keycloak identity** with realm-init, token-exchange, and auth-reconcile jobs bundled
  in the chart.
- **AgentGateway ext_authz bridge** enforces per-call MCP decisions before a request
  reaches a backend tool.
- **Centralized Authorization Service** (0.5.12+) made checks faster and consistent
  across agents, workflows, and tools.
- **Directory sync** — Okta and LDAP group sync on a schedule, JIT user provisioning on
  login, and transactional tuple reconciliation so hundred-group orgs sync without
  crashing. Later patches added DPoP, federated identity, throttling, filtering, and a
  baseline bootstrap.
- **Per-document RAG ACLs** enforced at retrieval time, propagated through every ingestor.
- **Admin tooling** — an access explorer, an RBAC self-check, team-scoped admin views,
  policy downloads, and stale-grant cleanup on sync.

Enable with:

```yaml
tags.keycloak: true
openfga.enabled: true
openfgaAuthzBridge.enabled: true
global.agentgateway.enabled: true
```

### Workflow engine

A first-class workflow engine backed by LangGraph, superseding the old Task Builder.

- Multi-step workflows that fan out to sub-agents, pause for approval, and resume.
- **Inline human-in-the-loop** — the approval form renders in the chat card itself.
- **Subagent timeline correlation** — each sub-agent's output pins to its triggering step.
- **Run sharing** with teams for collaborative debugging, through the same access model
  as everything else.
- **Non-admin creation** — team members build and run workflows scoped to their team.
- Live status links posted into chat when an agent starts a run.

### Custom agents

The dynamic agents runtime became the sole routing layer.

- Full agent CRUD from the UI — system prompt, LLM config, MCP tool selection — persisted
  in MongoDB and live immediately. No code, no Helm edits.
- **MCP endpoint normalizer** accepts bare hostnames, trailing slashes, or a missing
  `/mcp` suffix and canonicalizes them.
- Fresh installs auto-provision a working Hello-World agent and a default team.
- Agent owners and their team members get manage access automatically.
- Editor blocker hints for missing config; the platform default agent cannot be deleted.
- Import agents from YAML (0.5.38).

### BYO credentials and impersonation

- **Envelope-encrypted credential store** — AES-GCM with KMS-style data-key wrapping in
  MongoDB. Use `aws-kms` in production; `local-cmk` is for non-production only.
- **Pin OAuth connections to MCP servers** so credentials are forwarded on every tool call.
- **PKCE public-client OAuth** for integrations where a fixed connection scope is wrong.
- **Service account passthrough** — service accounts carry their own credentials.
- **Impersonation tokens** via Keycloak token exchange, so automated runs execute as the
  owning user with identical enforcement.
- **Fail-closed** — a caller-scoped tool with no credentials errors clearly instead of
  proceeding.

Enable with `CAIPE_CREDENTIALS_ENABLED: "true"` and `CREDENTIAL_KEY_PROVIDER: "aws-kms"`.

### Webex bot

- A full Webex integration as a first-class subchart, disabled by default
  (`tags.webex-bot: false`).
- Space-to-agent routing, self-service from the Integrations tab; bulk onboarding for admins.
- Native markdown rendering, "Run As" service-account identity, Prometheus metrics.
- **Multiple bots and per-surface default agents** (0.5.55) — run several Webex bots from
  one deployment.
- A Webex Meetings MCP server (0.5.37).

### Scheduled agents

- **`mcp-scheduler`** exposes create/list/update/delete for scheduled jobs, each owned by
  its creator.
- Kubernetes CronJob backend; the `caipe-cron-runner` pod fires once per interval and exits.
- **Owner impersonation on execution** — enforcement matches an interactive run, so a
  revoked owner means a failed run.
- Every run creates a visible conversation in the owner's chat history.
- Cron expressions for recurring jobs, plus delayed one-shots with retry metadata.

Enable with `scheduler.enabled: true`.

### Multimodal chat (0.5.63 – 0.5.66)

- Attach files to chat messages as multimodal model input, shown inline in the transcript.
- Slack attachments forwarded as multimodal input.
- Per-model input capabilities declared up front, degrading cleanly and naming the model
  in the skip warning.
- Attachment bytes offloaded to object storage; input attachments capped.
- A dropped-input-files panel in the admin metrics tab.

### Platform, RAG, and operations

- **Platform health dashboard** (0.5.16, overhauled in 0.5.25) and admin **Insights**
  with drill-down (0.5.61) and RBAC scoping (0.5.56).
- **Audit service** with configurable retention (0.5.17, 0.5.27).
- **Remote MCP catalog** (0.5.59) and self-service integrations (0.5.20).
- **Knowledge bases refactor** and a self-service RAG ingestion-source config store; S3
  ingestor and RAG file uploads.
- **Unified application navigation and settings** with breadcrumbs (0.5.68).
- **Object storage from a shared `global.storage.s3` block** (0.5.68).
- Keycloak on PostgreSQL, an AgentGateway config-bridge, a setup wizard, Ollama and
  LiteLLM support, and Prometheus metrics for Keycloak and OpenFGA.
- The documentation site moved to the `caipe.io` root and became responsive.

## Fixes

Sixty-plus patch releases went almost entirely to reliability. The themes:

- **Authorization correctness** — scoped team admins can manage their own team; agent
  owner access; unlinked service-account grants preserved across visibility changes;
  OpenFGA batch-check limits; caller-keyed tool authorization.
- **Identity sync** — Okta sync throttling and reliability, auto-create team sync,
  Keycloak 26.x robustness and upgrade reconciliation, AD group filtering.
- **Sessions** — configurable session lifetime (0.5.53) and the SSO idle-timeout fix
  (0.5.61).
- **Slack and Webex** — file-attachment routing, agent pagination, name parsing,
  ephemeral nudges, Workflow Builder mentions, escalation config, two-tab space navigation.
- **Chat** — deprecated-agent recovery, private chat access, subagent HITL resume, tool
  result invariants, failed conversation deletes no longer reappear.
- **CI** — native per-arch image builds (0.5.58) replaced emulated multi-arch builds;
  third-party MCP image versions pinned.

## Security

- Keycloak service-account client secrets rotate on every install/upgrade, with a
  strict-mode gate (`keycloak.strictClientSecrets`) that fails the install if a dev
  placeholder still mints a token.
- The BFF no longer falls back to `admin/admin` against Keycloak — production requires
  `client_credentials` against a confidential client and fails loudly otherwise.
- Demo users with hardcoded passwords removed from the bundled realm config.
- MongoDB strict-password gate (`mongodb.auth.strictPasswords`) fails fast on placeholders.
- SSRF protections in web ingestors; NoSQL injection fixes in the admin API.
- Catalog credential boundaries enforced; max-age on signed OAuth state cookies.
- Dependency vulnerability sweeps and exact pins across the series.

## Breaking changes

**No breaking Helm values changes from 0.4.18** for operators who are not opting into
RBAC, Webex, or credentials. Everything new is additive with working defaults.

| Version | Change | Who is affected |
|---|---|---|
| 0.5.0 | `active_team` JWT claim removed, replaced by channel-derived team binding | Only code that read the claim; 0.4.18 never issued it |
| 0.5.3 | AgentGateway routing defaults to `static` (CRD-free) | Set `global.agentgateway.routingMode: gateway-api` if you rely on Gateway API CRs |
| 0.5.8 | Catalog API key digests moved from SHA-256 to HMAC-SHA256 | Keys minted before 0.5.8 fail verification — re-mint them |
| 0.5.10 | Slack slash-command prefix follows `APP_NAME` | Only if automations hardcode `/caipe` and you changed `APP_NAME` |
| 0.5.17 | NPS survey and Admin → NPS tab removed | `nps.enabled` is ignored; drop it from values |
| 0.5.22 | Legacy supervisor and standalone A2A agents removed | Drop `supervisor.*` / `a2a-agents.*` values; dynamic agents are the routing layer |
| 0.5.24 | `agentSecrets` deprecated in favour of `mcpSecrets` | Still functional; migrate for forward compatibility |
| 0.5.49 | New channel onboardings default to mention-only | Existing channels unaffected; set `listen: "all"` to opt out |
| 0.5.55 | Webex bot defaults move from env vars to a structured `bots` array | Only `tags.webex-bot: true` deployments |
| 0.5.62 | `agentgateway.authz.restrictedMcpServers` defaults to `[]` | Re-add entries if you deliberately restricted a server |

### 0.4.18 → 0.5.x

Drop-in for a stock 0.4.18 deployment. The only required review is whether your
`values.yaml` references components that no longer exist.

**Keys to drop** (no-ops from 0.5.22 onward):

- any `supervisor.*` config
- `a2a-agents.*` standalone agent entries
- `AGENT_GATEWAY_MCP_SERVER_IDS: "jira"` — AgentGateway routes by profile now
- `nps.enabled` — removed in 0.5.17

**Recommended adoption sequence:**

| Step | What to enable | Key values |
|---|---|---|
| 1 | Dynamic agents | already the default, no change |
| 2 | RBAC + OpenFGA | `tags.keycloak`, `openfga.enabled`, `openfgaAuthzBridge.enabled`, `global.agentgateway.enabled` |
| 3 | Webex bot | `tags.webex-bot: true` |
| 4 | Credentials store | `CAIPE_CREDENTIALS_ENABLED: "true"`, `CREDENTIAL_KEY_PROVIDER: "aws-kms"` |
| 5 | Scheduler | `scheduler.enabled: true` |

### Data migrations

No MongoDB schema migration is required for the drop-in path. New collections back the
credential store and Slack/Webex route management, created lazily when the matching
feature is enabled.

If you enable RBAC, the OpenFGA init job bootstraps the authorization model and backfills
tuples on first run — there is no prior store to migrate from. Enabling Keycloak
initializes the `caipe` realm and token-exchange clients.

Two admin-run migrations are registered for this series (Admin → Migrations): `0.5.1`
and `0.5.8`. Run them if you adopt RBAC or the catalog API keys.
