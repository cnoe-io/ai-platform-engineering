> Series: **0.4.0 – 0.4.18** (2026-04-23 → 2026-05-22)
> Chart: `oci://ghcr.io/cnoe-io/charts/ai-platform-engineering:0.4.18`
> Previous series: 0.3.x · Next series: [0.5.x](/releases/release-0.5.x)

## Highlights

0.4.x restructured the platform around the **AG-UI protocol** and made the Next.js
gateway the single front door. Streaming, conversation storage, and auth stopped
being per-client concerns: the web UI, Slack bot, and dynamic agents all speak one
event model and share one conversation API.

The series then spent 18 patches building out the Skills platform, adding
human-in-the-loop tool approval, and hardening the runtime for real deployments.

## Features

### AG-UI protocol and the Next.js gateway

- **One streaming model** — the AG-UI event model replaced legacy A2A streaming across
  dynamic agents, the Slack bot, and the UI. Stream events are persisted server-side
  behind a `StreamEncoder` abstraction (`AGUIStreamEncoder`, `CustomStreamEncoder`).
- **All traffic through the gateway** — flat `/api/v1/chat/` routes authenticated with
  `X-User-Context`. Dynamic agents no longer validate tokens or accept direct browser
  requests; config ownership (agents, MCP servers, models) moved to the UI.
- **Slack bot rewritten on AG-UI** — typing indicators with live thoughts, todo-aware
  streaming, subagent suppression, and bearer-token service-account auth.

### Shared conversation API

- Server-owned ID generation with an `idempotency_key` for cross-client dedup.
- A `client_type` enum (`webui` | `slack`) on every conversation.
- **Delta thread context** — follow-ups embed only messages since `last_processed_ts`,
  which removed quadratic checkpoint growth on long Slack threads.

### Skills platform

Five releases reworked Skills end to end (0.4.1, 0.4.2, 0.4.4, 0.4.7, 0.4.11):

- Unified Workspace browsing every hub (GitHub, GitLab, local) in one view.
- Standalone scanner microservice, decoupled from the gateway.
- Multi-source hubs, install history, ZIP export, and AI Assist for authoring.
- Skills Builder for dynamic agents, plus gallery filter/sort controls.

### Human-in-the-loop and workflows

- **Tool approval (0.4.9)** — agents pause for explicit human approval before running
  a sensitive tool, with GridFS-backed artifact storage for large payloads.
- **Workflow service and default agent (0.4.13)** — the first workflow runtime and a
  platform default agent so fresh installs are usable on first login.

### Integrations and MCP

- **AWS MCP server** and a Pod Security Standards baseline (0.4.8).
- **LiteLLM FinOps MCP server** for model cost and usage queries (0.4.12).
- `curl` against private endpoints from the agent runtime (0.4.15).

### Operations

- **DocumentDB compatibility (0.4.5)** — the runtime works against AWS DocumentDB, not
  just vanilla MongoDB.
- **Installer UX and runtime simplification (0.4.6)** — fewer prompts, fewer moving parts.
- Documentation site redesign (0.4.9).

## Fixes

- **Slack and chat reliability (0.4.14)** — followup prompts no longer claim knowledge of
  replies the agent never made; VictorOps escalation config accepts `escalation_policy`.
- **RAG truncation and seed persistence (0.4.16)** — long retrieved documents are no
  longer silently cut, and seeded config survives restarts.
- **Scrapy 2.16 crawl fix (0.4.17)** — web ingestion works again after the upstream bump.
- **Dynamic agent chat regression (0.4.18)** — restored chat for agents created through
  the UI editor.
- **Admin statistics** — feedback dedup keyed on `(permalink, user_email)` and Slack
  feedback upsert keyed on `(message_id, user_id)`, fixing double-counted feedback and
  broken top-user linkage.

## Breaking changes

0.4.0 carried the breaking changes for the series. 0.4.1 through 0.4.18 were drop-in
upgrades, with two exceptions noted below.

| Version | Change | Impact |
|---|---|---|
| 0.4.0 | `env:` block removed from all components — use the flat `config:` map | **High** |
| 0.4.0 | `caipe-ui.seedConfig.*` → `caipe-ui.appConfig.*` (and `SEED_CONFIG_PATH` → `APP_CONFIG_PATH`) | **High** |
| 0.4.0 | `slack-bot` values fully restructured to a flat `config:` map | **High** |
| 0.4.0 | `slack-bot.slack.tokenSecretRef` → `slack-bot.existingSecret` | **High** |
| 0.4.0 | `dynamic-agents` OIDC/CORS keys removed — auth is handled by the gateway | **High** |
| 0.4.0 | `dynamic-agents.config.AUTH_ENABLED` → `DEBUG: "true"` for dev bypass | Medium |
| 0.4.3 | Slack `botConfig` channel schema: `qanda`/`ai_alerts`/`ai_enabled` → flat `agents` list | **High** |
| 0.4.10 | `overthink.custom_prompt` removed from the Slack bot config | Low |

## Upgrade guide: 0.3.x → 0.4.x

Everything below applies once, when moving off 0.3.x.

### 1. CAIPE UI

**Merge `env:` into `config:`.** All environment variables live in one flat map.

```yaml
# Before (0.3.x)
caipe-ui:
  env:
    SKILLS_DIR: "/app/data/skills"
  config:
    SSO_ENABLED: "true"

# After (0.4.x)
caipe-ui:
  config:
    SKILLS_DIR: "/app/data/skills"
    SSO_ENABLED: "true"
```

**Rename `seedConfig:` to `appConfig:`** and drop `enabled:` — the ConfigMap is created
automatically when any of `models`, `mcp_servers`, or `agents` is non-empty. The chart
swaps `SEED_CONFIG_PATH` for `APP_CONFIG_PATH` on your behalf.

### 2. Dynamic agents

- Merge `env:` into `config:`, then delete the `env:` block.
- Remove `AUTH_ENABLED`. For a local dev bypass use `DEBUG: "true"`; in production omit
  it entirely.
- Remove `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_REQUIRED_ADMIN_GROUP`, and
  `CORS_ORIGINS`. These belong to `caipe-ui` now — dynamic agents never see a browser
  request.

### 3. Slack bot — most of the work

Named keys are replaced by a flat `config:` map plus a top-level `existingSecret:`.

| Old key (0.3.x) | New key in `config:` |
|---|---|
| `appName` | `APP_NAME` |
| `botMode` | `SLACK_BOT_MODE` |
| `caipeApiUrl` | `CAIPE_API_URL` |
| `silenceEnv` | `SLACK_INTEGRATION_SILENCE_ENV` |
| `slackWorkspaceUrl` | `SLACK_WORKSPACE_URL` |
| `env.*` | move into `config:` |
| `mongodb.uri` | `MONGODB_URI` (consider a Secret instead) |
| `mongodb.database` | `MONGODB_DATABASE` |
| `auth.enabled` | `SLACK_INTEGRATION_ENABLE_AUTH` |
| `auth.tokenUrl` | `OAUTH2_TOKEN_URL` |
| `auth.clientId` | `OAUTH2_CLIENT_ID` |
| `auth.scope` | `OAUTH2_SCOPE` (omit if empty) |
| `auth.audience` | `OAUTH2_AUDIENCE` (omit if empty) |
| `prompts.responseStyle` | `SLACK_INTEGRATION_PROMPT_RESPONSE_STYLE` |
| `prompts.qanda` | `SLACK_INTEGRATION_PROMPT_QANDA` |
| `prompts.overthinkQanda` | `SLACK_INTEGRATION_PROMPT_OVERTHINK_QANDA` |
| `prompts.mention` | `SLACK_INTEGRATION_PROMPT_MENTION` |
| `prompts.humbleFollowup` | `SLACK_INTEGRATION_PROMPT_HUMBLE_FOLLOWUP` |
| `prompts.aiAlerts` | `SLACK_INTEGRATION_PROMPT_AI_ALERTS` |
| `slack.tokenSecretRef` | `existingSecret` (top level, same Secret) |

The Secret contents do not change: `SLACK_BOT_TOKEN`, `SLACK_APP_TOKEN`,
`SLACK_SIGNING_SECRET`, and optionally `OAUTH2_CLIENT_SECRET`.

**Bot config file moved.** `CAIPE_BOT_CONFIG` → `SLACK_INTEGRATION_BOT_CONFIG` (set by
the chart), and `/etc/caipe/caipe-bot-config.yaml` → `/etc/caipe/bot-config.yaml` in a
dedicated `*-bot-config` ConfigMap. If neither is present the bot starts with no channel
configuration and logs a warning rather than crashing.

**`botConfig` channels use a flat `agents` list.** The bot rejects the old keys with an
explicit error.

```yaml
# Before
botConfig:
  C012345678:
    name: "#example-channel"
    ai_enabled: true
    qanda:
      enabled: true
      include_bots: { enabled: true, bot_list: ["example-bot"] }
    ai_alerts: { enabled: false }

# After
botConfig:
  C012345678:
    name: "#example-channel"
    agents:
      - agent_id: "example-agent"
        users:
          enabled: true
          listen: "mention"   # "mention" | "message" | "all"
          overthink: { enabled: false }
        bots:
          enabled: true
          listen: "message"
          bot_list: ["example-bot"]
```

### 4. The unified config pattern

All components converged on the same shape:

```yaml
component:
  config: {}           # flat env vars → ConfigMap → envFrom
  existingSecret: ""   # pre-existing Secret → envFrom secretRef
  externalSecrets:
    enabled: false
  appConfig: {}        # structured YAML file, caipe-ui only
  botConfig: {}        # structured YAML file, slack-bot only
```

`config:` is always flat. No nesting, no `config.env:` sub-keys.

### 5. Pre-upgrade checklist

- [ ] Back up values: `helm get values ai-platform-engineering -o yaml > values-backup.yaml`
- [ ] `caipe-ui`: merge `env:` into `config:`, rename `seedConfig` → `appConfig`
- [ ] `dynamic-agents`: merge `env:`, drop `AUTH_ENABLED`, drop OIDC/CORS keys
- [ ] `slack-bot`: restructure named keys into `config:`, set `existingSecret`
- [ ] `botConfig`: replace `qanda`/`ai_alerts`/`ai_enabled` with the `agents` list
- [ ] `helm diff upgrade` before applying
- [ ] Deploy, then check pod logs for config-loading messages

### Rollback

`helm rollback ai-platform-engineering <previous-revision>` and restore the backed-up
values file. These are configuration-only changes, so no data migration has to be
undone — the 0.3.x chart expects the old structure and the old values file works as-is.
