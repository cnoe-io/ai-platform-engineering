> Previous series: [0.5.x](/releases/release-0.5.x)

## Highlights

0.5.22 removed the legacy supervisor and standalone A2A agents. 0.6.x finishes the job:
the data they left behind is cleaned up, and every admin surface that still assumed a
supervisor was in the loop now reads from the dynamic-agent runtime instead.

This is a consolidation series. There is one new user-facing feature — self-service Webex
identity linking — and a lot of deliberate subtraction.

<!-- truncate -->

## Features

### Self-service Webex identity linking

Users link and relink their own Webex account from Settings, instead of filing a request
for an admin to map it. The admin panel shows the linked account's email rather than a raw
Webex id.

### Admin insights, metrics, and health on dynamic-agent telemetry

The Insights, Metrics, and Health surfaces were built against supervisor metrics that no
longer exist. They now read the dynamic-agent series:

- `da_turns_total{agent_name,model_id,turn_type,status}` and
  `da_turn_duration_seconds` for throughput, success rate, and latency.
- `da_llm_calls_total`, `da_tool_calls_total`, and `da_active_requests` for load.
- Health checks target the dynamic-agents job rather than a supervisor job.

Chat now persists `agent_name` and a measured `latency_ms` on assistant messages, so
"Top Agents" and response-time charts populate for real. The **Tokens Used** card was
removed rather than left showing zero — the dynamic-agent stream encoders do not emit
token usage.

## Cleanup

The subtraction, in one place:

- **Legacy runtime data** — a new `legacy_runtime_cleanup_v1` migration drops orphaned
  `checkpoints_*` and `checkpoint_writes_*` collections, and unsets
  `metadata.agent_version` / `metadata.model_used` on conversations and `a2a_events` on
  messages. See [Upgrade](#upgrade) before running it.
- **Dead UI** — the legacy agent builder, the orphaned workflow editor, an orphaned
  sandbox screen, and unreferenced public assets are gone. Agent pickers are now
  consistently searchable, and global navigation and breadcrumbs were reworked.
- **Dead authorization path** — the legacy OpenFGA authz path in dynamic agents is
  removed; the Centralized Authorization Service is the only path.
- **Dead build and repo scaffolding** — a stale agent chart scaffold, an orphan LiteLLM
  Compose overlay, obsolete Make targets, and an unsupported legacy workshop.
- **CI consolidation** — GHCR package paths are unified under one tree, third-party MCP
  images are pinned, and the RBAC and Playwright checks are back in the required set.

Also in the series: a customizable Home page with Quick Start and optional widgets, and
agent completion browser alerts.

## Fixes

- **Webex** — a check-then-write race on identity link claims, a false revision conflict
  on publication approval, and the Relink button staying live during an in-flight unlink.
- **Auth** — signed OAuth state cookies now carry a max age.
- **Skills** — zip import no longer loses ownership or file access.
- **Dynamic agents** — prompt rendering is immutable, so a rendered prompt can no longer
  be mutated between turns.
- Dependency vulnerability sweep across the tree.

## Breaking changes

No breaking Helm values changes. 0.6.0 is a drop-in upgrade from 0.5.69.

Two behavioural notes:

- The **Tokens Used** metric is gone from Insights and from `/api/users/me/insights` and
  `/api/users/me/stats`. Anything scraping those responses for a token count needs to stop.
- The legacy OpenFGA authz path in dynamic agents is removed. Deployments already on the
  Centralized Authorization Service (the default since 0.5.12) are unaffected.

## Upgrade

```bash
helm upgrade ai-platform-engineering \
  oci://ghcr.io/cnoe-io/charts/ai-platform-engineering \
  --version 0.6.0 \
  -f your-values.yaml
```

### Legacy runtime cleanup migration

The `0.6.0` migration in **Admin → Migrations** is **destructive and optional**. It drops
collections, so read this before running it:

- It preserves `checkpoints_conversation` (and its writes collection) and
  `workflow_checkpoints` (and its writes collection).
- It drops every other `checkpoints_*` / `checkpoint_writes_*` collection — those are
  orphans from the supervisor era with no reader left.
- It unsets `metadata.agent_version` and `metadata.model_used` on conversations, and
  `a2a_events` on messages.

Nothing in 0.6.x reads the data it removes, so the upgrade is safe without running it.
Run it when you want the storage back. Take a MongoDB backup first — the migration is not
reversible.
